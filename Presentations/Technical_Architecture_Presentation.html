System Invariants

Architectural Principles & Hard Constraints

Design rules governing deterministic synchronization, zero data loss, and resource governance.

⏱️ Wall-Clock Determinism
  • Recordings are split on absolute UTC wall-clock multiples of Storage.ChunkIntervalMinutes (default: 5 min).
  • Chunks align to 00:00, 00:05, 00:10 etc., independent of when individual station streaming commenced.
  • Ensures identical temporal bounds across all 100+ stations for effortless multi-track alignment.
🛡️ Dual-Path Failover Strategy
  • Primary Target: Central NetApp UNC storage path (Storage.NetAppUncPath).
  • Automated Fallback: If NetApp is unreachable within 3 seconds, Server auto-switches MediaMTX to local NVMe fallback (C:\ProgramData\...\Recordings).
  • Endpoint Local Cache: If LAN link drops, AgentWorker writes to local encrypted queue.
⚡ Zero-Overhead Hardware Encoding
  • Dynamic runtime encoder probing: NVENC → Intel QSV → CPU libx264 fallback.
  • Intel QSV reduces workstation CPU utilization by ~37% compared to software x264.
  • Desktop Duplication API (DirectX DDA) captures GPU framebuffers directly without GDI memory copying.

Endpoint Internals

Endpoint Architecture: Session 0 vs. Session 1 Isolation

Solving Windows security boundaries: Capturing user desktop graphics from a persistent background service.

🛑 The Windows Session 0 Barrier
  • Since Windows Vista, system services run in Session 0, which has no interactive desktop, no display monitor access, and no Direct3D graphics context.
  • Direct3D Desktop Duplication API (DDA) can only run within the interactive user session (Session 1+).
  • If an application runs solely as a user program, it terminates when the user logs off, failing continuous surveillance requirements.
// Win32 Interop in AgentSupervisorService: WTSGetActiveConsoleSessionId(); WTSQueryUserToken(activeSessionId, out userToken); DuplicateTokenEx(userToken, MAXIMUM_ALLOWED, ...); CreateProcessAsUser(..., "AgentWorker.exe", ...);
✅ Two-Tier Supervisor-Worker Solution
  • AgentSupervisorService (Session 0):
    Runs as a persistent Windows Service with SYSTEM privileges. It monitors user logon/logoff events and acts as the watchdog.
  • Elevation to Interactive Desktop:
    Upon active user login, Supervisor duplicates the user desktop token and invokes Win32 CreateProcessAsUser to spawn AgentWorker.exe directly into Session 1.
  • Local IPC Coordination:
    Supervisor and Worker communicate via a private local Named Pipe / IPC channel for clock calibration, stream targets, and telemetry reporting.
Media Pipeline

AgentWorker Ingestion: DDA, WASAPI & Video Pacer

Capturing display surfaces and mixed audio with microsecond timing accuracy.

🖥️ DirectX Desktop Duplication (DDA)
  • Acquires frame surfaces straight from the GPU frame buffer via IDXGIOutputDuplication.
  • Zero memory copy across CPU boundaries until the frame is piped into the hardware encoder.
  • Captures native multi-monitor display resolutions up to 4K at steady 30 FPS.
  • Automated session recovery via SessionGuard if workstation resolution changes or screen locks.
// High-Precision Multimedia Timer applied at startup: WindowsNative.TimeBeginPeriod(1); // 1ms scheduler granularity Process.GetCurrentProcess().PriorityClass = ProcessPriorityClass.High; Thread.CurrentThread.Priority = ThreadPriority.Highest;
🎙️ WASAPI Audio & Video Pacing
  • Dual Loopback Mixer: Uses Windows Audio Session API (WASAPI) to capture system speaker audio mixed simultaneously with the local microphone.
  • AudioPacer Synchronization: Solves timestamp drift between independent audio clock and display refresh rate by continuous sample counting and audio byte pacing.
  • Loopback TCP Handshake: Audio samples are streamed via high-speed local TCP loopback into FFmpeg, eliminating standard Windows pipe buffer bloat.
Encoding Engine

Tri-Tier Hardware Acceleration (NVENC → QSV → CPU)

Dynamic hardware probe executing at stream startup to eliminate workstation CPU load.

🟢 Tier 1: NVIDIA NVENC
  • Encoder: h264_nvenc
  • Preset: p2 (Fast / Low Latency)
  • Tuning: -tune ll -forced-idr 1
  • CPU Overhead: < 1% CPU utilization
  • Latency: Zero-latency B-frame suppression
🔵 Tier 2: Intel QuickSync (QSV)
  • Encoder: h264_qsv
  • Preset: veryfast -low_power 1
  • Pixel Format: Auto-converted to nv12
  • CPU Efficiency: ~37% less CPU than software x264 on standard office PCs
  • Enables hardware encoding on laptops and integrated GPU fleets
🟡 Tier 3: CPU Fallback
  • Encoder: libx264 (Software)
  • Preset: ultrafast
  • Tuning: -tune zerolatency
  • Safety Margin: Activated only when no supported discrete or integrated GPU is detected.
Storage Engine

Deterministic Wall-Clock Chunking Engine

Synchronizing MediaMTX segment cuts to round clock boundaries without cumulative drift.

⏰ Boundary Calculation Logic
// RecordingChunkScheduler.cs: Compute boundary from UTC clock var now = DateTime.UtcNow; int interval = _storageConfig.ChunkIntervalMinutes; // e.g. 5 int minutesSinceMidnight = now.Hour * 60 + now.Minute; int nextBoundaryMinutes = minutesSinceMidnight - (minutesSinceMidnight % interval) + interval; // Exact sleep until next tick (no cumulative Task.Delay drift): var nextTick = now.Date.AddMinutes(nextBoundaryMinutes); await Task.Delay(nextTick - DateTime.UtcNow, ct);

At boundary tick, MediaMtxApiClient calls RotatePathRecordingAsync() on active streams, toggling record: false → true to force an immediate clean segment close.

📌 MediaMTX Pinning & Upstream Patch
  • Version Pin: MediaMTX is strictly pinned to v1.15.4.
  • The Upstream Bug (v1.15.5+): Later releases enforce an unconfigurable ntpDriftTolerance check in format_fmp4_track.go that falsely flags live screen capture jitter, splitting chunks every 15-20 seconds instead of the configured 5 minutes!
  • Deterministic Filenames: Formatted with %Y-%m-%d_%H-%M-%S-%f, matching the exact millisecond boundary of the cut.
Storage Strategy

Storage Architecture & High-Availability Failover

Guaranteed persistence across enterprise SAN/NAS outages and local disk constraints.

🏛️ Primary: NetApp UNC
  • All station segments write directly to Storage.NetAppUncPath.
  • Organized by station subfolders:
    {root}/live/{station_id}/*.mp4
  • High throughput enterprise SAN/NAS backend designed for 30+ day retention.
🔄 Dynamic Failover Resolver
  • StoragePathResolver tests NetApp responsiveness every chunk boundary with a 3-second timeout.
  • If NetApp is unreachable, MediaMTX is instantly reconfigured to write to local NVMe:
    C:\ProgramData\...\Recordings
  • When NetApp returns, subsequent chunks transition back automatically without server reboot.
🧹 Retention & Quota Safety
  • Time-Based Retention: MediaMTX automatically purges segments older than Storage.RetentionDays (e.g. 30 days).
  • Quota Safety Guard: Active recordings within 2 * ChunkInterval are shielded from eviction.
  • Safe Fallback: If total capacity exceeds quota, oldest non-shielded segments are pruned globally.

Catalog Engine

Storage Scanner & Automated Cataloging Pipeline

Continuously reconciling on-disk MP4 files with the database to index finalized segments.

🔄 Scan & Reconciliation Cycle
  • StorageScannerService runs a low-priority background sweep across the active recordings root directory.
  • Parses timestamp metadata encoded in segment filenames:
    stationA_2026-10-15_13-15-00-000.mp4
  • Inspects unfinalized chunks using ffprobe to extract exact frame count, actual duration, codec, width, height, and audio stream presence.
  • Marks chunks as is_finalized = 1 once MediaMTX closes the write handle and releases the file.
🛡️ Resiliency Features
  • Self-Healing Catalog: If the server restarts unexpectedly, the scanner detects existing files on disk and restores missing database entries automatically.
  • Orphan Cleanup: Chunks recorded while the server was down or during network split-brain are discovered and ingested seamlessly.
  • Non-Blocking Queries: Timeline playback requests query the database covering index without touching the physical file system.

Time Continuity

Gap Handling & "No Signal" Clock-Alignment Engine

Solving temporal desynchronization when stations reboot, disconnect, or power down.

⚠️ The Desynchronization Challenge

In traditional NLE systems, if Station A records continuously from 10:00 to 10:30, but Station B was powered off from 10:10 to 10:20, simply concatenating Station B's clips results in a 10-minute video phase desynchronization. Multi-screen playback will show Station B's 10:20 actions at 10:10!

🛡️ The NoSignalPatternService Solution
  • SynchronizationPlanBuilder scans chunk timestamps and identifies temporal gaps greater than 500ms.
  • For every missing timespan, NoSignalPatternService synthesizes a calibrated "NO SIGNAL" / black synthetic video stream with the exact dimensions and duration of the gap.
  • Audio channels generate synthetic silence to match.
  • Outcome: Station tracks remain 100% time-synchronized throughout the entire export window down to the exact millisecond!
Forensic Telemetry

Forensic Keystroke Capture & Synchronized SRT

Capturing operator keyboard events with millisecond timestamps for synchronized subtitle display.

⌨️ Low-Level Keyboard Capture
  • KeyboardCaptureFactory initializes a low-level OS hook (SetWindowsHookEx / X11).
  • Calculates absolute UTC epoch milliseconds calibrated with server clock offset.
  • Privacy & Safety Gate: Keystroke capture automatically pauses whenever the agent is in standby or offline gap modes, preventing leak of unrecorded input.
  • Batched into C2 telemetry reports to eliminate per-key network overhead.
📄 SubRip (.SRT) Subtitle Generation
  • KeystrokeSrtGenerator queries keystroke_events across the requested extraction time range.
  • Assembles human-readable subtitle tracks formatted with exact start and end display intervals:
    1 00:01:14,200 --> 00:01:15,800 [KEY] Ctrl+Shift+Esc (Task Manager) 2 00:01:18,450 --> 00:01:20,100 [KEY] Enter (Execute Command)
  • Exported alongside video files for seamless playback in VLC, browser players, or court forensic suites.
